## 背景：为什么要研究状态

WebRTC 有**多层并行状态**，每层独立变化，混在一起就让人懵：

```
信令连接状态(WS)     ── 我连上服务器了吗？
呼叫状态(Call)       ── 这次通话到哪一步了？
ICE 状态(PC内部)      ── P2P 通路打通了吗？
DataChannel 状态      ── 数据通道能用了吗？
```

排查 bug 的第一步永远是：**先问"卡在哪个状态"**。本章把各层状态做成对照表，作为排查工具。

## 状态清单（骨架：先把已知枚举抄录于此，待逐条详解）

### 5.1 信令连接状态（本项目自定义，`signaling.dart` 顶部）
| 枚举值 | 含义 | 触发时机（代码位置待补） |
| --- | --- | --- |
| `ConnectionOpen` | WS 已连接、已注册 | `onOpen` |
| `ConnectionClosed` | WS 断开 | `onClose` |
| `ConnectionError` | 出错 | 错误路径 |

### 5.2 呼叫状态（本项目自定义）
| 枚举值 | 触发时机 |
| --- | --- |
| `CallStateNew` | 主叫 invite 建会话 / 被叫收到 offer |
| `CallStateInvite` | 主叫发出 offer |
| `CallStateRinging` | 被叫收到 offer 等待应答（相机端自动 accept） |
| `CallStateConnected` | 收到对方 answer 并 setRemoteDescription 完成 |
| `CallStateBye` | 收到/发出 bye |

> 注意：`CallStateConnected` ≠ 画面已出，仅表示 SDP 交换完。黑屏还要查 ICE/media 状态 → 见 07 章黑屏排查。

### 5.3 RTCPeerConnection 层状态（flutter_webrtc 原生枚举）
- [ ] `signalingState`：`stable / have-local-offer / have-remote-offer / closed`（SDP 协商状态机）
- [x] `iceConnectionState` ★排查黑屏最常用：

| 值 | 含义 | 排查动作 |
| --- | --- | --- |
| `new` | 还没开始连通性检查 | 信令没通 / 没交换到候选 → 查 `04` 章 4.1/4.3 |
| `checking` | 正在对候选对做 STUN Binding | 正常，等 |
| `connected` | 找到可用候选对 | **通了**；此时黑屏查媒体面（`07` 章 3.1） |
| `completed` | 所有检查结束 | 正常 |
| `failed` | 所有候选对都失败 | 查 TURN：凭据是否拉到（4.0.3）、是否对称 NAT |
| `disconnected` | 曾通、现在断（可能恢复） | 弱网抖动；别急着销毁，观察是否回 `connected` |
| `closed` | PC 已关闭 | 生命周期结束 |

- [ ] `iceGatheringState`：`new / gathering / complete`

### 5.4 DataChannel 状态
- [x] `connecting / open / closing / closed`；为什么发消息要判 `dc.state == open`：`sendData()/sendBinaryData()` 都先检查 `dc != null && dc.state == RTCDataChannelOpen`，否则消息静默丢失——DC 虽随会话一起创建（label `fileTransfer`），但 open 要等 ICE 通了才发生。

## 5.1 用状态定位问题的方法论

> 状态：🟢 已填充（2026-11-17）

排查任何"连不上/黑屏/掉线"，**第一步永远是先问"卡在哪一层"**，再对症下药：

| 层 | 断的表现 | 先查什么 |
| --- | --- | --- |
| 信令(WS) | `ConnectionClosed/Error` 反复打转 | host/port/证书（`07` 章 3.3）；服务端日志有无 `On message` |
| 注册 | 连上了但 `peers` 里没有自己 | `new` 消息是否发出；设备 ID 是否合法 |
| 发现 | `peers` 里没有相机 | 相机端 WS 是否存活；`camera_online` 与 `peers` 双通道对照（`04` 章 4.5） |
| 呼叫 | offer 发出后无 answer | 相机端 Ringing 是否回调；邮箱校验是否拒绝 |
| 媒体 | `CallStateConnected` 但黑屏 | `iceConnectionState`（5.3 表）；轨绑定与渲染（`07` 章 3.1） |
| 数据 | DC 消息发不出去 | `dc.state == open`？label 是 `fileTransfer` |

## 5.2 本项目连接生命周期：connect → 注册 → peers → 呼叫 → 通话 → bye/leave

> 状态：🟢 已填充（2026-11-17）
> 对应代码：`rephone-security/lib/services/signaling.dart`（`connect/invite/accept/onMessage`）、`utils/device_info.dart`、`pages/monitor_viewer_page.dart`

**阶段一：连接前准备**
1. 设备 ID 生成/读取（持久化，`SharedPreferences`，key 前缀 `device_id_`）：Android 用 `ANDROID_ID+随机种子` hash，iOS 用 `identifierForVendor`，最终格式 `{8位hash}_{角色}`，如 `03959381_camera` / `0f2a11c4_monitor`。
   - 三个约束：固定不变（注册名+DB 关联）；角色含在 ID 里；**不含 `-`**（服务端用 `-` split 会话双方的硬前提，见 `04` 章 4.5）。
2. `connect()`：拉 TURN 凭据（失败静默退回纯 STUN，见 `04` 章 4.3.2）→ 建 WSS `/ws` → 注册回调 → `socket.connect()`。

**阶段二：注册与发现**

```mermaid
sequenceDiagram
    participant M as 监控端(monitor)
    participant S as 信令服务器 /ws
    participant C as 相机端(camera)

    M->>S: TLS WebSocket 连接
    M->>S: new {id: xxx_monitor, name, user_agent}
    S->>S: peers[xxx_monitor]=conn（非相机ID，不改 online）
    S-->>M: peers [相机..., 其他...]
    C->>S: TLS WebSocket 连接
    C->>S: new {id: yyy_camera, name, user_agent}
    S->>S: peers[yyy_camera]=conn; camera_online=1
    S-->>C: peers [...]
    S-->>M: peers 更新(含 yyy_camera)
    Note over M: onPeersUpdate → 找到 yyy_camera
    M->>M: 延迟500ms 自动呼叫
    M->>S: offer {to:yyy_camera, media:'video'}
    S->>C: offer（原样转发）
```

监控端收到 `peers` 后自动找绑定相机呼叫；**相机不在列表即判定离线，直接退出页面**（`monitor_viewer_page` 的 `onPeersUpdate` 分支）。

**阶段三：呼叫与通话**（信令细节见 `04` 章 4.2/4.6）

- 主叫 `invite()`：`sessionId = 主叫ID-被叫ID` → 建 PC → **先建 DataChannel('fileTransfer')**（视频会话也带，用于控制消息）→ `createOffer` → 发 offer；`CallStateNew → CallStateInvite`。
- 被叫收到 offer：新会话则 `setRemoteDescription`（远端候选缓冲统一补加）→ `CallStateNew → CallStateRinging` → 校验邮箱 → 自动 `accept` → answer。已存在同 id 的 PC 则走**重协商**分支（对讲场景，见 `04` 章 4.2）。
- 主叫收到 answer：`setRemoteDescription` → `CallStateConnected`（≠ 画面已出，见 5.2 节开头注意）。

**阶段四：会话内**
- 对讲：`setMonitorTalkbackEnabled(true)` → 首次采集麦克风 `addTrack` + 重新 offer（renegotiation）；关闭只 mute 不重协商。
- DataChannel 业务：回放/事件列表走 JSON 请求，录像文件以二进制分块回传。

**阶段五：结束** → 见 5.4 异常路径。

## 5.3 心跳保活与断线重连机制详解

> 状态：🟢 已填充（2026-11-17）
> 对应代码：`signaling.dart` 的 `_startKeepalive/_scheduleReconnect/onClose`

| 机制 | 参数 | 说明 |
| --- | --- | --- |
| Keepalive | 每 `15s` 发一次 `keepalive` | 探活信令链路；服务端**原样回显**，客户端**不校验回包**——真正的断线感知依赖 WS close/error。15s 是为防公网 NAT/运营商对空闲 TCP 的回收 |
| 重连间隔 | `3s` | `_scheduleReconnect()` 定时后重新 `connect()` |
| 重连上限 | `999999`（近无限） | 监控/相机是常驻场景，**永不放弃**直到成功或主动 close |
| 主动关闭 | `close()` 置 `_isClosing=true` | 页面销毁时调用；此后不再自动重连 |

触发重连的入口：WS `onClose`、`onError`、**keepalive 发送抛异常**。重连成功后 `_reconnectAttempts` 清零。

```dart
_socket?.onClose = (int? code, String? reason) {
  _stopKeepalive();
  _isSocketOpen = false;
  onSignalingStateChange?.call(SignalingState.ConnectionClosed);
  if (!_isClosing) {
    _scheduleReconnect();     // 3s 后重连，近无限次
  }
};
```

> 设计反思：无限重连适合常驻设备，但**重连成功 ≠ 会话恢复**——旧 PC/旧会话不会自动重建，UI 层要靠 `peers`/`CallStateBye` 回调重新走一遍发现与呼叫流程。

## 5.4 异常路径梳理：bye vs leave vs peers 消失

> 状态：🟢 已填充（2026-11-17）

| 场景 | 服务端动作 | 监控端感知 | 监控端动作 |
| --- | --- | --- | --- |
| 主动挂断 `bye` | 按 session_id 拆双方，**向两端各发一条 `bye`** | `CallStateBye` | 关 PC/DC、释放对讲麦克风 |
| 相机断线（WS close） | `camera_online=0`；从 `peers` 删除；广播 `leave {peerId}`；再广播全量 `peers` | ① `leave` 回调 ② `peers` 更新发现相机消失 | 两条通道殊途同归：`_closeSessionByPeerId()` 清会话回调 `CallStateBye` / Toast 离线后返回上一页 |
| 自己 WS 断 | （对服务端）删 peer + 广播 leave | —— | 3s 后自动重连（5.3）；重连后重走发现/呼叫 |

> ⚠️ 内存纪律：所有会话清理路径必须走 `dc.close() + pc.close() + pc.dispose()`（只 close 不 dispose 会泄漏 native PeerConnection 直至 OOM，见 `07` 章 P1）；页面整销毁还要停本地轨并释放对讲麦克风流。

## 5.5 状态机时序总图

> 状态：🟢 已填充（2026-11-17）

```mermaid
flowchart TD
    A[监控端启动/进入监控页] --> B[生成/读取 monitor 设备ID]
    B --> C[拉取 TURN 凭据]
    C --> D[建立 WSS /ws]
    D --> E[发送 new 注册]
    E --> F[收到 peers 广播<br/>每15s keepalive]
    F --> G{绑定相机是否在线?}
    G -- 否 --> H[提示离线并退出]
    G -- 是 --> I[invite 相机<br/>建 PC + DataChannel]
    I --> J[offer → 服务器 → 相机]
    J --> K[相机 Ringing → 自动 accept → answer]
    K --> L[监控端 Connected<br/>P2P 视频/音频/数据]
    L --> M{通话中}
    M -- 相机掉线/bye --> N[leave/bye 广播<br/>相机 online=0]
    N --> O[清理会话, 返回上一页]
    M -- 挂断 --> P[发送 bye, 本地销毁PC]
    D -- 连接断开 --> Q[3s后自动重连(无限)]
    M -- 网络波动/心跳失败 --> Q
```
