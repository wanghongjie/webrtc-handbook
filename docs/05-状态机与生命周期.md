## 背景：为什么要研究状态

WebRTC 有**多层并行状态**，每层独立变化，混在一起就让人懵：

```
信令连接状态(WS)     ── 我连上服务器了吗？
呼叫状态(Call)       ── 这次通话到哪一步了？
ICE 状态(PC内部)      ── P2P 通路打通了吗？
DataChannel 状态      ── 数据通道能用了吗？
```

排查 bug 的第一步永远是：**先问"卡在哪个状态"**。本章把各层状态做成对照表，作为排查工具。

### 5.1 信令连接状态（本项目自定义，`signaling.dart` 顶部）
| 枚举值 | 含义 | 触发时机（代码位置待补） |
| --- | --- | --- |
| `ConnectionOpen` | WS 已连接、已注册 | `onOpen` |
| `ConnectionClosed` | WS 断开 | `onClose` |
| `ConnectionError` | 出错 | 错误路径 |

### 5.2 呼叫状态（本项目自定义）
| 枚举值 | 触发时机 |
| --- | --- |
| `CallStateNew` | 主叫 invite 建会话 / 被叫收到 offer |
| `CallStateInvite` | 主叫发出 offer |
| `CallStateRinging` | 被叫收到 offer 等待应答（相机端自动 accept） |
| `CallStateConnected` | 收到对方 answer 并 setRemoteDescription 完成 |
| `CallStateBye` | 收到/发出 bye |

> 注意：`CallStateConnected` ≠ 画面已出，仅表示 SDP 交换完。黑屏还要查 ICE/media 状态 → 见 07 章黑屏排查。
