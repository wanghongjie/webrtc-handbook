    03 音视频与媒体基础¶

    状态：🟡 骨架 + 3.5 已填充 ｜ 难度：★★☆☆☆ 本章要解决的问题：画面到底是怎么从"摄像头"变成"另一台手机屏幕上的一帧"的？

    为什么需要这一章¶

    前面 01 章已经知道媒体是 P2P 的 RTP 包。但"打包"之前，音视频原始数据经历了 采集 → 编码 → 封包；接收端反向 拆包 → 解码 → 渲染。这一章把中间的每一步讲透，理解后才能回答诸如： - 为什么分辨率/帧率约束写在 getUserMedia 的 mandatory 里？ - 为什么 SDP 里会列出 H.264/VP8 一堆编码？ - 为什么偶发卡顿/马赛克？（丢包、无 FEC/NACK） - 为什么相机端 CPU 发热？（编码很贵）

    3.5 远端流渲染：从 MediaStream 句柄到屏幕上的一帧¶

    状态：🟢 已填充 对应代码：rephone-security/lib/pages/monitor_viewer_page.dart、rephone-security/lib/services/signaling.dart；flutter_webrtc 原生侧 下文用 $PUB 代指 ~/.pub-cache/hosted/pub.flutter-io.cn/flutter_webrtc-1.6.0。

    一句话结论：Dart 侧的 MediaStream 只是一个「查表用的句柄」，真正被渲染的是原生 libwebrtc 里的 VideoTrack；渲染器唯一的绑定点是 videoTrack.addSink(renderer)。

    3.5.1 先破除误解：Dart 的 MediaStream 里没有任何像素¶

    // $PUB/lib/src/native/media_stream_impl.dart
class MediaStreamNative extends MediaStream {
  MediaStreamNative(super.streamId, super.ownerTag);

  factory MediaStreamNative.fromMap(Map<dynamic, dynamic> map) {
    return MediaStreamNative(map['streamId'], map['ownerTag'])
      ..setMediaTracks(map['audioTracks'], map['videoTracks']);
  }

    它只持有三样东西：

    字段 含义 作用
    streamId 流 ID 查表主键
    ownerTag 归属标记；远端流 = peerConnectionId，本地流 = "local" 查哪张表的次键
    _audioTracks / _videoTracks 轨道元数据（id / kind / label / enabled） 只用来判断「有没有视频轨」，不含像素

    关键认知：它是句柄（handle），不是数据容器。像素始终留在原生 libwebrtc 的 VideoTrack 里，Dart 侧永远不经过。

    3.5.3 srcObject = stream：四次查表才落到 VideoTrack¶

    ① Dart   setter → invokeMethod('videoRendererSetSrcObject',

    3.5.4 addSink：唯一的绑定落点¶

    // $PUB/android/.../FlutterRTCVideoRenderer.java:249
private void tryAddRendererToVideoTrack() throws Exception {
  if (videoTrack != null) {
    EglBase.Context sharedContext = EglUtils.getRootEglBaseContext();
    if (sharedContext == null) { /* 直接放弃渲染，避免 SurfaceViewRenderer.init 抛异常杀进程 */ return; }

    surfaceTextureRenderer.release();
    listenRendererEvents();
    surfaceTextureRenderer.init(sharedContext, rendererEvents);
    surfaceTextureRenderer.surfaceCreated(producer);

    videoTrack.addSink(surfaceTextureRenderer);   // ★ 渲染真正开始的地方
  }
}
    • addSink 是 libwebrtc 的标准观察者接口。从这一行起，解码线程每产出一帧就回调 SurfaceTextureRenderer.onFrame()。
    • 每次都先 release() 再 init()：换轨（simulcast 层切换 / 重新绑定）时必须重建 GL 状态与 rendererEvents。
    • EglUtils.getRootEglBaseContext() 是全局共享的 EGL 上下文——全 App 共一套 GL 纹理与 shader，这也是为什么必须判空（共享上下文没初始化好，渲染器无从创建）。
    • 反向解绑在 setVideoTrack(null) 分支 → videoTrack.removeSink(surfaceTextureRenderer)。

    3.5.5 一帧的生命周期：Android 与 iOS 走了两条完全不同的路¶

    Android iOS
    帧入口 SurfaceTextureRenderer.onFrame(VideoFrame) FlutterRTCVideoRenderer.renderFrame:
    传递方式 GPU 共享：EGL 直接画到纹理背后的 Surface CPU 拷贝：I420 → CVPixelBuffer
    旋转 libwebrtc / GPU 完成 手写 RTCYUVHelper I420Rotate
    通知引擎 提交 EGLSurface（引擎自行合成） [_registry textureFrameAvailable:_textureId]
    引擎取数 无需回调 引擎主动调 copyPixelBuffer
    开销 低（无拷贝） 每帧一次 memcpy + 旋转

    Android：Surface 在第一帧到达时才创建，producer.setSize() 用帧的旋转后分辨率：

    // $PUB/android/.../SurfaceTextureRenderer.java:100
public void onFrame(VideoFrame frame) {
  synchronized (surfaceLock) {
    if (surface == null) {
      producer.setSize(frame.getRotatedWidth(), frame.getRotatedHeight());
      surface = producer.getSurface();
      createEglSurface(surface);
    } else if (frameSizeChanged(frame)) {
      // The producer's backing buffers are fixed-size: setSize() only takes
      // effect for a Surface obtained afterwards. Without recreating the EGL
      // surface here, a simulcast layer upgrade keeps rendering into the old
      // low-resolution buffer and the video stays blurry.
      releaseEglSurface(() -> {});
      surface = null;                                   // 先置空，避免 getSurface 抛异常后画进已释放的 Surface
      producer.setSize(frame.getRotatedWidth(), frame.getRotatedHeight());
      surface = producer.getSurface();
      createEglSurface(surface);
    }
  }
  updateFrameDimensionsAndReportEvents(frame);
  super.onFrame(frame);   // EglRenderer：投递到自己的渲染线程，用 GlRectDrawer 把帧画到 EGLSurface
}

    坑位：SurfaceProducer 的底层 buffer 是定长的，setSize() 只对「之后获取的 Surface」生效。所以在 else if 分支里必须 release EGLSurface → setSize → 重新 getSurface → createEglSurface。否则 simulcast 从低清层升到高清层时，画面会一直停留在旧的低分辨率上（模糊），而分辨率事件却已经上报给 Dart 了（表现为「布局变对了，画面还是糊的」）。

    iOS：多了一个节流标志，防止解码快于合成：

    // $PUB/ios/.../FlutterRTCVideoRenderer.m:194  renderFrame:
if(!_frameAvailable && _pixelBufferRef) {
  [self copyI420ToCVPixelBuffer:_pixelBufferRef withFrame:frame];
  if(_textureId != -1) { [_registry textureFrameAvailable:_textureId]; }
  _frameAvailable = true;
}

// $PUB/ios/.../FlutterRTCVideoRenderer.m:54  copyPixelBuffer（由引擎回调）
if (_pixelBufferRef != nil && _frameAvailable) {
  buffer = CVBufferRetain(_pixelBufferRef);
  _frameAvailable = false;   // 引擎取走后解锁，下一帧才能写入
}

    3.5.6 事件回流：尺寸 / 旋转 / 首帧如何让 widget 自动重排¶

    原生 RendererEvents.onFrameResolutionChanged / onFirstFrameRendered
        │  eventSink.success({event: didTextureChangeVideoSize, width, height, rotation})
        ▼  EventChannel('FlutterWebRTC/Texture$textureId')
Dart   eventListener: value = value.copyWith(width:, height:, rotation:, renderVideo:)
        │  RTCVideoRenderer extends ValueNotifier<RTCVideoValue> → 自动 notifyListeners
        ▼
RTCVideoView 的 ValueListenableBuilder rebuild
  → SizedBox(width: maxHeight * value.aspectRatio, height: maxHeight)
  → FittedBox(fit: BoxFit.contain / cover)

    aspectRatio 对旋转 90°/270° 会交换宽高：

    // $PUB/../webrtc_interface-1.5.1/lib/src/rtc_video_renderer.dart
double get aspectRatio {
  if (width == 0.0 || height == 0.0) return 1.0;
  return (rotation == 90 || rotation == 270) ? height / width : width / height;
}

    这条链上没有任何业务 setState。「横竖屏翻转时画面容器自动跟着变」完全由 ValueNotifier 驱动。

    3.5.7 渲染层实践要点与坑位¶

    点 说明
    为什么要赋两次 srcObject unified-plan 下 audio/video 的 onTrack 顺序不定；有视频轨时才绑主渲染器，音频轨后到再赋一次以刷新部分机型的播放（monitor_viewer_page.dart:102-103 注释）
    挂断时置 null :217 / :272 → 发 streamId: '' → 原生查到 null → setVideoTrack(null) → removeSink。纹理本身保留，下次通话可复用
    dispose() 必须调用 :82。原生侧 producer.release() + surfaceTextureRenderer.release() + eventChannel.setStreamHandler(null)；漏掉 = Flutter 纹理与 EGL surface 双重泄漏，反复进出页面会崩
    ownerTag 传错 = 静默黑屏 getStreamForId 查不到时静默返回 null，无异常、无日志。这是最难排查的一类渲染问题
    initialize() 幂等 Dart 侧用 Completer _initializing 保护，重复调用只 await 同一个 future（本项目在 initState 里 fire-and-forget 调用）
    renderVideo 是门闸 _textureId != null && _srcObject != null 才画 Texture，否则显示占位符——所以「已 initialize 但没设流」不会黑屏而是空白
    一套纹理一个渲染器 textureId 全局唯一、不跨页面共享；同页两个 RTCVideoRenderer = 两块 GPU 合成层
